# 数值表整理与引用规范

## 目标

让制作人、数值策划和 AI 能沿同一条路径理解并复核结论：

`方案/概览 → 输入与假设 → 推导过程 → 体验验证 → 配置输出 → dev/trunk 配置校验`

## Sheet 分类

| 类型 | 作用 | 修改原则 |
|---|---|---|
| 概览/方案 | 说明目标、版本、负责人和结论 | 必须保持为当前入口 |
| 输入/参数 | 可调整假设和外部数据 | 标明单位、来源和适用版本 |
| 推导/计算 | 中间过程和公式 | 不用不可解释的魔法数字 |
| 体验/验证 | 玩家分层、时长、投入产出和边界测试 | 写明样本/版本和判断标准 |
| 配置/输出 | 对应程序字段的结果 | 必须能反查推导页 |
| 历史/备份/竞品 | 旧版本或外部参考 | 原则上只读，不作为新结论唯一依据 |

## 引用要求

引用 Excel 结论时必须同时写明：

- 仓库相对文件路径；
- Sheet 名；
- 使用的版本或日期；
- 输入假设和关键公式所在区域；
- 输出结果与程序配置表的对应关系。

禁止在文档、脚本、注释或清单中记录成员电脑的绝对路径。

## 当前整理策略

现有源表包含大量线上使用公式和历史推导。本轮不批量改写单元格、公式、Sheet 顺序或
样式，以避免破坏计算链路；通过 `知识库/策划源表导航.xlsx` 标注推荐入口、配置页、
历史页和整理建议。后续逐表重构时，应先复制版本、对比公式与关键输出，再由负责人确认替换。

程序配置不复制进资源库。校验时直接只读目标 `dev` 或 `trunk`，记录 SVN URL 与
revision；不得为使分析结果一致而修改程序配置。
