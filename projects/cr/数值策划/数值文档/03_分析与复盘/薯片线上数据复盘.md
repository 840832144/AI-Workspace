## 1. 复盘范围

### 1.1 活动与时间

薯片对应 Activity `1033`：玩家通过 Slots Spin 获得活动积分，积分转为薯片，薯片用于活动内开盒/奖励推进，并关联 Jackpot 与 Pass 奖励。

本次主窗口由线上事件中的 `activity_start_stamp=1787562000`、`activity_end_stamp=1787821199` 确定：

- UTC0：`2026-08-24 09:00:00 <= #event_time < 2026-08-27 09:00:00`，共 72 小时；
- 项目 SQL 指南默认业务时区为 UTC+3，对应 `2026-08-24 12:00:00` 至 `2026-08-27 12:00:00`；
- `$part_date` 仅作为 `2026-08-24` 至 `2026-08-27` 的分区扫描条件，所有核心指标再用上述精确时间过滤。

用户范围为活动初始化事件 `event_20000 / reason=252` 覆盖的 886 名用户。来源字段均为 `Import_Tools`；该事件的版本、国家/地区字段为空，渠道虚拟属性查询失败，因此本报告不能进一步限定版本、渠道、服务器或地区。测试账号字段虽出现在 Schema 中，但服务端查询失败，本次人数未能排除测试账号。

## 3. 指标口径

| 指标 | 定义与公式 | 分母/单位 |
|---|---|---|
| 初始化用户 | `event_20000`、`activity_id=1033`、`reason=252` 的去重用户 | 886 人 |
| 积分触发用户 | `event_10074`、`activity_id=1033`、`reason=SlotMachineBet` 的去重用户 | 初始化用户 |
| 消费用户 | `event_20000`、`activity_id=1033`、`reason=254` 的去重用户 | 初始化用户或前一步交集用户 |
| 奖励领取用户 | `event_20001`、`activity_id=1033`、`reason=259` 的去重用户 | 初始化用户或严格消费交集用户 |
| 严格漏斗 | 每一步均为同一用户满足“初始化→积分→消费→领取”的集合交集 | 上一步交集用户 |
| 道具产出/消耗 | 产出=`reason=251` 的 `SUM(change)`；初始化赠送=`reason=252`；消耗=`reason=254` | 道具数量；方向由 reason 判定 |
| 付费分层强度 | 活动期成功付费用户/非付费用户中的消费量 ÷ 对应消费用户数 | 仅限已消费用户，不是活动付费转化率 |
| VIP 分层 | 对每名消费用户取窗口内最大 `viplevel`，分为 VIP0–1、VIP2+ | 消费用户；分组互斥 |

掉落命中率的正确口径应为“去重命中的合格 Spin 行为数 ÷ 合格 Spin 行为数”。现有积分事件没有可用于与 Spin 一一关联的 `source_spin_id`，因此不能把积分事件数或 `SUM(change)` 除以 Spin 数当作掉落率。根据业务确认，本次将掉落视为正常，不提出掉落配置调整。

## 4. 核心结果

### 4.1 严格漏斗

| 阶段 | 严格交集用户 | 相对上一步 | 相对初始化 | 计算 |
|---|---:|---:|---:|---|
| 初始化 | 886 | 100.00% | 100.00% | `886/886` |
| 产生积分 | 820 | 92.55% | 92.55% | `820/886` |
| 发生薯片消费 | 560 | 68.29% | 63.21% | `560/820`；`560/886` |
| 领取 Jackpot 奖励 | 443 | 79.11% | 50.00% | `443/560`；`443/886` |

已确认事实：最大流失发生在“产生积分→实际消费薯片”，流失 `260/820=31.71%`；第二处流失发生在“消费→奖励领取”，流失 `117/560=20.89%`。独立计数下，消费用户为 571 人（`571/886=64.45%`），奖励领取用户为 445 人（`445/886=50.23%`）；与严格漏斗的差异来自集合交集限制。

### 4.2 过程量与道具产消

- 积分触发：967,899 条事件、820 名用户，`SUM(change)=2,403,050,339`。这是事件量与字段累计值，不是掉落命中次数，也不用于计算掉落率。
- 玩法产出：`reason=251` 共 167,806 条记录、785 名用户，薯片变化量 202,394。
- 初始化赠送：`reason=252` 共 886 条记录、886 名用户，薯片变化量 4,430，即每人 5 枚。
- 玩法消费：`reason=254` 共 149,398 条记录、571 名用户，薯片变化量 149,398。
- 方向性库存差：`202,394 + 4,430 - 149,398 = +57,426` 枚；消费/总发放=`149,398/206,824=72.24%`。
- Jackpot 领取：`event_20001 / reason=259` 共 18,314 条记录、445 名用户。该事件没有 boxId、openId、luck 或奖励列表字段，因此“记录数”不能解释为开盒数，`itemnum` 也不能换算为美元奖励价值。

本地 v6 测算为每人最多 160 枚、初始 5 枚，886 人的简单上界为 `(160+5)×886=146,190` 枚；线上 `reason=251+252` 累计为 206,824 枚，高出 60,634 枚（`60,634/146,190=41.48%`）。这是明确的数据可比性异常，但不能直接判定程序超发：可能涉及事件重复、字段单位、循环重置或本地测算与线上正式配置版本不一致，需先补齐事件语义和正式配置快照。

### 4.3 付费表现

活动 72 小时内，项目级成功付费为 23 单、17 人、207.77 美元；前 7 天同星期/同 72 小时时段为 55 单、18 人、212.45 美元。当前窗口相对对照：付费人数 `-1/18=-5.56%`，收入 `-4.68/212.45=-2.20%`，订单数 `-32/55=-58.18%`。两窗口不是随机对照组，只能作为项目背景，不能把差异归因于薯片活动。

活动商品事件 `event_20006` 中仅观察到 Snack Pass 3 单、3 人、14.97 美元，占当前项目收入 `14.97/207.77=7.21%`；未观察到薯片礼包订单。由于没有曝光人数，不能计算商品转化率，也不能仅凭 0 单判断价格问题。

## 8. 结论

1. **已确认事实：**薯片初始化覆盖 886 人，严格全路径完成 443 人，完成率 50.00%；最大流失在积分产生后到薯片消费，阶段流失 31.71%。
2. **已确认事实：**已消费用户中，付费用户和 VIP2+ 的消费深度分别为对照组的 2.78 倍和 1.60 倍，但付费样本只有 7 人，不能外推因果。
3. **数据推断：**当前主要问题更接近流程/展示与数据可观测性，而不是掉落数值。用户有积分但未进入消费，以及消费后未形成可验证的领取闭环，是更直接的损失点。
4. **暂时无法确认：**实际美元奖励、开盒概率、保底与 Jackpot 是否符合设计。线上事件缺少开盒唯一标识和奖励明细，本地源表又不是已核验的线上正式配置快照。
5. **暂时无法确认：**线上累计发放超过简单上界是重复上报、单位/循环语义还是配置版本差异；当前证据不足以归类为程序 Bug。

## 9. 建议

1. 暂不修改掉落配置。保留当前掉落方案，后续若要数据复核，应补 `source_spin_id` 或等价唯一关联键，并用“去重命中 Spin/合格 Spin”计算命中率。
2. 优先检查积分获得后的活动入口提示、薯片余额反馈、首次消费引导和可领奖提示；目标是降低当前 31.71% 的积分→消费阶段流失。
3. 为开盒/奖励链补充或确认 `open_id`、box 类型、luck 变化、奖励明细、领取状态字段；在此之前不据 `event_20001` 记录数调整箱子概率或 Jackpot。
4. 用正式线上配置快照核对 160 枚上限、循环/重置规则和 `change` 单位，再解释 41.48% 的发放量偏差；先排查时区、去重、版本、单位和重复上报。
5. 商业化先补曝光与点击漏斗，再判断 Pass/礼包问题。当前 3 单 Pass、0 条礼包订单没有曝光分母，不支持直接降价。

## 10. 数据限制

- 活动事件无法核验版本、渠道、服务器、地区，也未能排除测试账号。
- 没有 Spin 与积分事件的一一关联键，无法独立计算掉落命中率；“掉落正常”为业务确认，不是本次 SQL 独立验证结果。
- `event_20001` 缺少开盒唯一标识和奖励明细，不能计算箱型分布、奖池价值、保底与 Grand 到达率。
- `itemnum` 在聚合后出现明显不可解释的大值，未用于美元价值与经济结论。
- 本地设计脚本是可复算测算，不是线上正式配置快照；设计值与线上量只能作偏差检查，不能直接作 Bug 定性。
- 项目级 Slots 与付费数据包含非活动用户，只作为同期背景；没有随机对照，不能归因于薯片活动。
