- 查询日期：2026-08-28
- 查询方式：数数 MCP，只读 SQL
- 项目：`newcr`
- project id：`61`
- 事件表：`v_event_61`
- 用户表：`v_user_61`（本次未查询用户明细）
- 主活动窗口（UTC0）：`2026-08-24 09:00:00 <= #event_time < 2026-08-27 09:00:00`

### Q02：初始化规模、来源与用户重合

```sql
WITH init AS (
  SELECT activity_id, "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20000'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034)
    AND reason = 252
  GROUP BY activity_id, "#user_id"
), flags AS (
  SELECT uid,
         MAX(CASE WHEN activity_id = 1033 THEN 1 ELSE 0 END) AS chips_init,
         MAX(CASE WHEN activity_id = 1034 THEN 1 ELSE 0 END) AS lucky_init
  FROM init
  GROUP BY uid
)
SELECT
  SUM(chips_init) AS chips_users,
  SUM(lucky_init) AS lucky_users,
  SUM(CASE WHEN chips_init = 1 AND lucky_init = 1 THEN 1 ELSE 0 END) AS overlap_users,
  COUNT(*) AS union_users
FROM flags
```

结果：薯片 886 人、777 886 人、交集 886 人、并集 886 人。另按 `source` 聚合，两活动初始化来源均为 `Import_Tools`。对应两份报告“复盘范围”和初始化分母。

## 4. 主漏斗

### Q03：严格用户交集漏斗

```sql
WITH init AS (
  SELECT activity_id, "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20000'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034) AND reason = 252
  GROUP BY activity_id, "#user_id"
), points AS (
  SELECT activity_id, "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_10074'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034) AND reason = 'SlotMachineBet'
  GROUP BY activity_id, "#user_id"
), consume AS (
  SELECT activity_id, "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20000'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034) AND reason = 254
  GROUP BY activity_id, "#user_id"
), reward AS (
  SELECT activity_id, "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20001'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034) AND reason = 259
  GROUP BY activity_id, "#user_id"
)
SELECT
  i.activity_id,
  COUNT(*) AS init_users,
  COUNT(p.uid) AS init_point_users,
  COUNT(c.uid) AS init_point_consume_users,
  COUNT(r.uid) AS full_path_users
FROM init i
LEFT JOIN points p ON i.activity_id = p.activity_id AND i.uid = p.uid
LEFT JOIN consume c ON i.activity_id = c.activity_id AND i.uid = c.uid AND p.uid IS NOT NULL
LEFT JOIN reward r ON i.activity_id = r.activity_id AND i.uid = r.uid AND c.uid IS NOT NULL
GROUP BY i.activity_id
ORDER BY i.activity_id
```

结果映射：

| 活动 | 初始化 | 积分交集 | 消费交集 | 奖励交集 |
|---|---:|---:|---:|---:|
| 1033 薯片 | 886 | 820 | 560 | 443 |
| 1034 777 | 886 | 821 | 592 | 335 |

对应两份报告“核心结果/严格漏斗”。777 的最后一步仅代表 `reason=259` 奖励事件，不等于所有格子奖励或最终完成。

## 6. 用户分层

### Q08：VIP 分层（每用户最大 VIP）

```sql
WITH per_user AS (
  SELECT
    activity_id,
    "#user_id" AS uid,
    MAX(viplevel) AS max_vip,
    SUM(change) AS consume_units
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20000'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034)
    AND reason = 254
  GROUP BY activity_id, "#user_id"
)
SELECT
  activity_id,
  CASE WHEN max_vip >= 2 THEN 'VIP2+' ELSE 'VIP0-1' END AS vip_group,
  COUNT(*) AS users,
  SUM(consume_units) AS consume_units
FROM per_user
GROUP BY activity_id, CASE WHEN max_vip >= 2 THEN 'VIP2+' ELSE 'VIP0-1' END
ORDER BY activity_id, vip_group
```

结果：薯片 VIP0–1 为 518 人/128,337，VIP2+ 为 53 人/21,061；777 VIP0–1 为 563 人/66,898，VIP2+ 为 53 人/10,216。对应两份报告“用户分层”。

### Q09：消费用户内的付费/非付费强度

```sql
WITH payers AS (
  SELECT "#user_id" AS uid
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_1005'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND ret = 0
  GROUP BY "#user_id"
), consumed AS (
  SELECT activity_id, "#user_id" AS uid, SUM(change) AS consume_units
  FROM v_event_61
  WHERE "$part_date" BETWEEN '2026-08-24' AND '2026-08-27'
    AND "#event_name" = 'event_20000'
    AND "#event_time" >= TIMESTAMP '2026-08-24 09:00:00'
    AND "#event_time" <  TIMESTAMP '2026-08-27 09:00:00'
    AND activity_id IN (1033, 1034)
    AND reason = 254
  GROUP BY activity_id, "#user_id"
)
SELECT
  c.activity_id,
  CASE WHEN p.uid IS NULL THEN 'nonpayer' ELSE 'payer' END AS payer_group,
  COUNT(*) AS consume_users,
  SUM(c.consume_units) AS consume_units
FROM consumed c
LEFT JOIN payers p ON c.uid = p.uid
GROUP BY c.activity_id, CASE WHEN p.uid IS NULL THEN 'nonpayer' ELSE 'payer' END
ORDER BY c.activity_id, payer_group
```

结果：薯片非付费 564 人/144,415，付费 7 人/4,983；777 非付费 608 人/75,817，付费 8 人/1,297。由于初始化用户与全局付费用户的补充联表返回数数服务端通用错误，本次不报告活动初始化池的付费渗透率。

## 11. 复现注意事项

1. 先调用 `get_sql_guide`，再执行 SQL；每条查询都必须保留 `$part_date` 限制。
2. 活动时间以线上 `activity_start_stamp/activity_end_stamp` 为准；不要只用自然日。
3. 先按事件分别汇总，避免跨事件引用不属于该事件的字段。
4. `reason=254` 的 `change` 在线上为正数，消费方向由 reason 语义判定。
5. 不以 `event_10074` 事件数或 `SUM(change)` 计算掉落率；缺少 Spin 唯一关联键时应标记不可计算。
6. `quest_turn/quest_turn_level` 只作深度标记，不能当作严格顺序完成事件。
7. `itemnum` 未经单位与奖励语义确认，不换算为美元。
8. 如需重跑付费分层，继续只返回聚合结果，不导出用户 ID。
