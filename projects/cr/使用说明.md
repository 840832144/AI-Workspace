# CR 使用说明

日常入口为 AI-Workspace 的 `projects/cr/`；先读[项目 README](README.md)和[工作流](WORKFLOW.md)。根 Agent 规则、Task 分配和角色交接在同一次克隆中可见。

## 1. 阅读与输入

先确认任务范围，再从数值文档、知识库目录定位原始材料。源表与历史附件默认只读；需要当前程序配置时核对目标公司 SVN 项目、完整 URL、dev/trunk 和 revision 后直接读取。不重建退役的程序配置导出快照。

## 2. Skills

按 [项目规则中的五个 Skill](AGENTS.md#skill-路由)选择；正文唯一保存在 `.agents/skills/`。旧 `cr-audit-config-snapshots` 已退役。TRAE、Codex、ChatGPT 共用同一正文与证据口径。

## 3. 设计与验证

方案包含目标、来源、假设、公式、边界与回滚；业务参数从明确环境取值。改表须另获授权，保留非目标 Sheet/公式，并复核实际单元格差异。目录工具只生成检索资料，不改变源表，也不替代业务验证。默认不做重复哈希校验。

## 4. 写入位置

日常文档、Skills 和分析工具提交 AI-Workspace 的 `projects/cr/` 分支/PR；正式配置仍在公司 SVN 工作副本制作与提交。资料同步先 dry-run；`--apply` 和 SVN `--execute` 需该任务明确授权。本次迁移均不执行。命令与路径见[工具说明](数值策划/工具/README.md)。

## 5. 历史与当前

下方第 6 节是迁移前已有示例，保留原数字、路径和 revision 作为历史记录，不构成现在修改配置的指令；当前操作以以上规则和实际 Task 为准。HuuugeCollector 副本仅供历史阅读。

## 6. 完整示例：建筑3中后期提高30%难度

### 6.1 原始需求

> 降低建造模块建筑3的消耗返还，并把建筑3中后期难度提高30%，提出修改方案、更新配置、提交到 dev，并附提交成功证据。

### 6.2 口径定义

| 项目 | 本次定义 |
|---|---|
| 建筑3 | `BuildLevelCfg.level = 3` |
| 中后期 | 60 个配置节点的后 50%，即 `blockNum = 31–60` |
| 难度 | 每个翻地节点的建设币消耗 `needCash` |
| 返还 | Spin、宝箱、荣誉、NPC 等建设币产出保持不变 |
| 返还/消耗比 | 固定返还 ÷ `needCash` |
| 取整 | `ceil(旧值 × 1.30 ÷ 50) × 50` |

没有修改 `BuildCashCheatSheet`，因为该表按 Bet、玩家等级和 VIP 查值，会影响所有建筑，无法只作用于建筑3。

### 6.3 修改方案

只修改 dev 配置：

```text
BuildLevelCfg.xlsx
└─ Sheet1
   └─ level=3, blockNum=31–60
      └─ needCash × 1.30，向上取整到50
```

以下内容保持不变：

- 建筑3前 50% 的 `needCash`。
- 所有节点的 `honorVal`、`expVal`、`npcMax`、`npcOne`。
- `SpinDropBuildingCoins` 的概率与基础掉落数量。
- `BuildCashCheatSheet` 的 Bet/等级/VIP 系数。
- `BuildBox` 和 `BuildHonorLevel` 的奖励。
- 其他建筑的全部配置。

### 6.4 修改前后结果

| 修改节点数 | 30 | 30 | 仅 block 31–60 |

| 建筑3中后期累计消耗 | 14,500,100 | 18,850,650 | +30.0036% |
| 建筑3全章累计消耗 | 14,867,000 | 19,217,550 | +29.2631% |
| 中后期返还/消耗比 | 100% 基准 | 76.92% | -23.08% |

由于采用 50 为取整单位，每行实际提高范围为 30.0000%–30.0439%。

### 6.7 风险、监控与回滚

当前建筑3中后期在修改前已经占全章累计消耗的 97.5%，因此本次虽然只改后半段，仍会让全章累计消耗提高 29.2631%。在建设币产出、Bet 选择和在线时长不变时，理论完成时长也会近似按同一比例增加。

上线后建议监控：

- 建筑3的 P50/P90 完成时长。
- block 30、48、49、60 的到达率与流失率。
- 玩家建设币不足次数及平均等待 Spin 数。
- 建筑3阶段的建设币产出/消耗比。
- 调整前后玩家等级、VIP 和 Bet 分层差异。

回滚条件建议：

- 建筑3 P50 完成时长提高超过 35%。
- block 49 后退出率提高超过 5 个百分点。
- 建设币不足导致的连续等待超过目标上限。

需要回滚时，以 r5418 的 `BuildLevelCfg.xlsx` 为基线恢复建筑3 block 31–60 的 `needCash`，重新执行单元格差异校验，并通过一次新的 SVN 提交完成回滚；不直接改写历史版本。
