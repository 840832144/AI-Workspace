## Scope

### A. 建立证据清单

先列出每份资料的类型、版本或 commit、文件哈希、可读性、保密等级与覆盖范围。完整阅读两份 CR 原文及其中图片形式的规则表。表格裁切、正文缺失或视频时段不可见必须单列未知，不能补写。

区分：原研究报告声称什么、视频实际看见什么、本轮重新核验了什么、尚未核验什么。保留来源自己的术语和章节，不静默修正、统一或替换原案。原研究可作为线索，不是自动继承的实锤。

### B. 从玩家体验拆 Pop，固定六个主题

| 主题 | 应说明内容 | 最小证据要求 |
|---|---|---|
| 人数与机台分布 | 可见机台组、座位数、在座/走动/站立角色、空位分布与疏密 | 文件时间码和可见范围；局部镜头不外推全场人数，遮挡座位不猜计数 |
| 角色行为与节奏 | 出现、走动、落座、游玩、庆祝、离座、换台或离场的实际顺序 | 跟踪同一可观察角色的连续片段；只有起点或终点时不能算完整持续时间 |
| 空位与玩家入座 | 点空位、点有人座位、点整组机台的反馈，是否等待或让位 | 现有资料中对应的点击与后续表现；身份无法确定时不称机器人专用规则 |
| 大厅与机台内一致性 | 进入玩法前后角色与座位是否连续，返回后的变化 | 配对时间码；同头像不自动证明后台同一快照实现 |
| 身份与资料连续性 | 可见资料类别、外观重复、同角色短时连续性 | 使用匿名角色别名，避免账号信息；短视频不证明跨日稳定与后台身份库规模 |
| 游玩与中奖表现 | 动作、头像反馈、机台效果、庆祝节奏与同步程度 | 可见事件计数及观察时长；动画频率不等于真实 Spin、中奖概率或实际奖励 |

每个主题都给出“现象 → 证据 → 能支持的结论 → 局限 → 对策划的意义”。没有覆盖到的主题也保留，说明缺口，不用常识填满章节。

### C. 原研究的证据审阅附录

将房间/用户、角色行为、模拟用户三层框架，以及原研究所列行为状态机和 `sitUser` 等符号，按“原报告记载”的身份保留为附录线索。需要核验的主张逐条列出原主张、来源、支持程度、缺失证据。

函数名不单独证明完整调用链、全部用户来源、机器人补位阈值、让位触发或服务端调度算法。账号编号、地区、Guest 名称等分布特征本身不单独证明自动控制；不重发具体账号、姓名、余额或原始响应。若有可审阅的进一步证据，按证据说明结论；没有则标为待验证。目标是准确利用已有研究，不是为了反驳或迎合旧结论而另写推断。

User 提出的“看着每台只空一位”应与实际片段并列：记录可见组数与时间范围，不写成所有房间恒定规则。用户对迁移空位底线的选择放入私有讨论表，不冒充 Pop 实测。

### D. CR 对照讨论表

按私有规格逐项对照 CR 已有要求，区分已有共性、真实差异、新增参考和未验证项。特别核对座位快照连续性、人数分布、非在座氛围、空位底线、点击有人座位时的排队/让位口径，以及身份与模拟数据的玩家感知价值。

原文中不同口径并列保留，由负责人讨论，不自动消除差异。基于 CR 数字的计算写明公式和假设，标为本轮对照推导，不能当 Pop 数据。

讨论表包含收益、代价、待确认问题和决策空栏。未与负责人对齐前，默认“待讨论”；不得填写虚构会议纪要、负责人姓名、已采纳结论、研发工期或上线日期。
