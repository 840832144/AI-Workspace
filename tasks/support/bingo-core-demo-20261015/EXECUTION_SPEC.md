## 3. Scope：完整玩法，不做外围系统

交付大厅→选卡/Bet面板（含取消）→开局→叫号与手工填格→充能与九道具→Bingo→结束补填→结果→返回大厅→再次入局。先选当前研究普通房间为参考；原版规则无法核验时按User暂定规则完成可玩版本，差异可查。

默认1卡，支持1/2/4/6卡，最多6卡；若dsh证实该参考模式的卡数档位不同，列明证据并调整对应配置。暂不实现成长解锁系统，试玩配置可开放6卡。每张卡的数字、FREE、已填状态、buff、Bingo结果相互独立，不能复制同卡凑数量。

采用固定场景库作为当前牌库方案：固定卡面集合、出球序列/时序、外部Bingo扣减脚本。场景至少支持6张合法卡并有明确子集选择。尚未恢复的原版选牌/随机算法不影响开发；用自制合成场景，不装入真实账号对局或Raw。道具抽取、目标随机与出球使用分开的随机来源/脚本，保证玩家不同点击不会悄悄改变固定出球序列。

Bet与门票消费、每卡Bingo上限分开配置。按User已给的回退方案，查不清原等级关系时使用5档Bet映射每卡1/2/3/4/5次，默认1；该映射标为暂定，覆盖早期“Bet绝不影响Bingo”的绝对表述。不因此更改卡面、出球或道具概率。门票/体力为可重置的本地测试数，不依赖线上余额或充值。

remainingBingos是剩余次数，不是秒数。初始数字和外部减数使用可配置场景脚本；无需其他玩家显示或真实多人后台。“其他人是假效果”只保留User假设，不写成原版事实。自己的每次已授予Bingo使剩余计数-1，最低为0；普通线型和魔方来源可分别计数，边界见第7节。

Non-goals：多人资料/匹配、XP/金币资产、成长、商店/充值、宝箱/卡包系统、云部署、复杂特效/原版素材迁移、原APK接本地服、恢复原自动玩、自动填数字策略及GM产品。自动使用道具是本次玩法，不属于被排除的Auto Play。测试场景和规则单元测试不扩展成GM控制台。

## 4. 九道具与统一处理

下列ID为Demo命名，不当作原协议ID。每次使用对所选全部卡逐卡处理；一张卡没目标不影响其他卡。合法使用只消耗一次道具/满槽，不按卡重复消耗；请求本身非法或进度未满属于拒绝，不冒充“已使用但无效果”。

|品质/ID|功能|首版局内实现|
|---|---|---|
|Normal N1|单格填充|每卡随机填min(1,合格数)格。|
|Normal N2|金币buff|每卡随机一个无buff空格放金币标记；填中保留触发状态，不发金币。|
|Normal N3|XP buff|每卡随机一个无buff空格放XP标记，成功放置时清该卡其他未填XP标记；无新目标则不为造目标先清旧标记。无XP发放。|
|Rare R1|双格填充|每卡无放回选择最多2格，有1格仍填1格。|
|Rare R2|宝箱buff|每卡一个无buff空格放宝箱标记；保留触发，不开箱、不发奖。|
|Rare R3|炸弹buff|每卡一个无buff空格放炸弹；被填中后填上下左右紧邻格，不含斜角、不越卡边界。炸到炸弹或魔方继续触发。|
|Epic E1|补填buff|每卡一个无buff空格放补填标记；该buff所在格首次被填时记录补填次数+1，可累积。放置本身不加次数。|
|Epic E2|魔方buff|每卡一个无buff空格放魔方；填中产生一次魔方Bingo，可与同次产生的普通线型Bingo分别计算。|
|Epic E3|×2 buff|每卡一个无buff空格放×2；填中触发一次两倍标记并清同卡其他未填×2标记，保持2、不叠乘4/8。局外奖励不发放。|

FREE不是随机目标，不作为新填格充能。填格与buff放置分离；放图标不等于已填，使用道具不等于放置/触发成功，放置补填buff不等于赚到补填次数。对失败/跳过目标仍记录原因，但UI不播放一个不存在的成功结果。

同一个格未填→已填只能一次，同一buff实例只触发一次；重复输入、相邻炸弹互炸不能重复获得Bingo/进度/補填次数。已填邻格跳过，合法连锁不被粗暴关闭。效果队列依次处理状态变化和后续事件，保存来源、父事件和稳定次序，禁止用动画回调作为规则裁决。

用户已给的流程为：每次填格增加进度，满槽后手动点击使用，自动模式满槽自动使用。手动和自动使用同一规则入口。暂按稀有度抽取、同稀有度内三种等权；三档之间的权重仍待考证，不能从截图数字推成概率。阈值、具体增量、满槽溢出、抽取时机、冷却及各填格来源是否充能均可配置，未证实项按第7节记录。不得为了令自动模式看似可用，偷偷新增自动填数字策略。

## 5. 结束与补填

建议实现阶段为Playing → Closing → EndBonus → Result → Lobby；名称为自研设计，不是原协议。

正常计数到0关闭普通叫号与玩家填格入口，先处理已合法接受的当前动作及有限连锁，再执行已赚到的补填。每个补填buff触发事件记录sourceCard、sourceCell和数量，避免现在不清楚归属就丢掉来源。每次结算补填从当时剩余合法目标选格，0目标跳过；补填引发的Bingo+n加入最终总数，不能在补填前封存结果。

补填次数全局/逐卡归属和结算中再次触发补填buff如何处理是当前待核验项；采用显式配置与第7节临时值，不隐式决定。结束阶段不得再次开放普通自动抽道具循环。剩余Bingo计数在0截断，不因新增Bingo再次触发结束；最终结算只生成一次。

对局结束的玩法条件与应用超时保护分离。旧自动玩的300秒、票券限额、十局>90%均不是本Demo玩法或验收条件。退出/返回按钮必须能正常收尾，不能要求策划因旧脚本截止手动清除残留弹窗。

## 6. 技术路线与移交

优先Unity客户端＋不依赖UnityEngine的C#规则内核Bingo.Core＋本地.NET规则服务。Codex先短检查团队版本/模板、已有Editor及构建模块，复用现有工具；能构建就直接推进，不另做长期选型研究。未知Unity版本时不得猜“团队正在使用某版本”。需要付费激活、安装授权或团队提供模板时仅提出具体事项，纯C#规则与本地服继续开发。

客户端只发送玩家动作并显示服务端状态/事件。规则时钟、随机源和配置显式注入，规则内核不依赖场景、坐标、网络、磁盘或动画。共享协议类型、schemaVersion、ruleVersion、scenarioId、roundId、递增事件序号及动作去重规则；本地server裁决唯一，不在客户端复制另一套Bingo算法。优先团队既有传输方案，无适用方案就用单一简单本地请求/事件接口，不建立账户/匹配/微服务平台。

第一次交付以Windows可执行包为目标：解压→一键启动本地服及客户端→试玩；试玩者不安装Unity Editor、IDA、模拟器或采集器。服务仅绑定回环地址，运行不连接原游戏。启动器检查就绪、识别启动失败，只停止自己启动的Demo进程；一键检查/停止、可重置本地测试资源、可回退到前一个包。

移交包括纯C#核心源码和兼容构建、版本化协议/配置/固定场景、Unity包或导入脚本、示例场景和自动测试。按团队兼容目标打包，不把现代.NET宿主当Unity插件导入。实际在最小Unity工程验证一次规则包导入与结果一致；界面/动画跨引擎自动转换不作承诺。若必须采用浏览器表现层作为临时切片，仍共用C#规则服务，公开标为临时交付，不把网页当Unity最终验收。

首版只有数字、格子状态、buff图标/文字、进度圈、手动/自动道具开关、Bingo计数和结果。复杂特效、原资源提取/迁移不是前置。原客户端本地兼容及未来GM只保留Roadmap Ideas，不启动。
