## 2. 必须修改

### R1 / P1：接通真实数据与运行流程，不能只交付固定 Blocked 入口

**依据：**实现 `bv_autoplay.py` 的 `preflight()` 固定返回 Blocked，`main()` 的 `--start` 没有实例化并调用控制器。`run()` 只轮询事件、处理球和 tick，没有调用 `setup_grid()` 或前台/导航采样；`go_next_round()` 固定停止。`tick()` 把上行事件记为观察，但不存在经过验证的填充确认路径。`bv_evidence.measure()` 对所有非 synthetic 输入追加 `production_semantics_unverified`。这是明确披露的局部候选边界，不是“代码全做完了，只缺十局测试”。

**做什么：**在原工具链内补齐最小生产绑定，不重写通用框架。

1. 先复用已有受控样本、协议解析和可用的结构化只读观察，建立卡组归属、叫号、当前普通押注/实际支出、对局关闭的字段与来源对应关系。数据完整性由可复核来源证明，不能手填 `closed=True`、`denominator_complete=True` 或改证据标签放行。
2. 为剩余填充语义提供最多两局定位用的受控诊断入口。诊断允许在已核验实例、普通押注和资源边界内进行正常界面操作，以收集尚未验证的填充观察；其输出必须是诊断证据，不计入正式验收。不能要求“先有已完成语义证明才能启动收集该证明的实验”，也不能为打破循环直接放开生产验收。
3. 用同局、同卡组、一次合法点击前后的结构化变化及重复独立样本验证有效填充判据；区分普通填充、特殊效果、包装信息和未知字段。不强制恢复全协议或全部 token，也不要求不存在的服务端逐格 ACK；经过验证的客户端接受状态可以使用，但必须准确标明证据层级，上行请求本身不能当成功。
4. 接通“检查 → 买卡 → 卡面绑定 → 等待布局稳定 → 按已叫号合法点击 → 确认/有限补漏 → 数据闭局 → 结算/续局”。采集接收不被截图或慢输入阻塞；实时补排只能使用当时可见数据。图像仅低频导航、前台/遮挡判断和几何标定，不承担业务数字识别或填充统计。
5. 每局形成独立冻结证据，生产核验器独立于控制器 done 集合。闭局、切局和终止路径均有实际调用，不用固定秒数到时伪装完整对局；低证据场景保留下界或 N/A。

**成功表现：**真实入口不再是常量占位，正常流程及失败路径均有可重放证据；至少两局定位证明选定语义在声明范围内稳定，再冻结版本与计量口径进入连续十局验收。

**失败怎么办：**保留实现与可核验的局部成果，准确列出缺失字段、来源、尝试结果和失败关卡。不得改旗标强行放行、回到截图数格或反复只提交“仍为 Blocked”。资源不足或当前金额不可核验时中止相关消费动作，不重新要求 User 批准已经确认的任务范围。

### R2 / P1：生产验收必须隔离 synthetic，并验证十个不同对局与真实批次

**依据 A：**`measure()` 对合格 synthetic 夹具会返回 `hard_pass=True`；`bv_autoplay.main()` 的 `--results` 只据此返回 exit 0，没有生产验收来源检查。最小复现：纯合成四卡、20 个目标、19 个确认 → `evidence_kind=synthetic`、`rate=0.95`、`hard_pass=True`，实际摘录 CLI 分支退出 0。结果虽然带 synthetic 标签，但测试算术通过与生产达标的成功信号没有隔离。

**依据 B：**`aggregate()` 只检查结果数量为十，以及 status/evidence_kind 字符串。`measure()` 返回结果不保留 round/session/instance 身份，批次函数也没有预登记清单或唯一性检查。最小复现：把一个显式标为 observed-live 的合成结果对象复制十次，即使十条均附加同一个 round_id，仍返回 `qualified=True / hard_pass=True / optimization_pass=True / weighted_rate=0.95`。这只是合成反例，不是真实十局。

受评测试 `test_thresholds_zero_and_weighting` 也把 synthetic 结果的字符串标签改成 observed-live 后做算术测试；这可以测试算术，但不能作为真实批次来源校验测试。

**做什么：**

- 分离“算术自测通过、证据有效、真实验收通过”字段和入口。synthetic 可以验证公式，但不得使生产验收成功；生产模式必须检查来源，不能只看 `hard_pass`、退出码或可编辑标签。
- 核验结果保留 batch_id、实例/会话身份、round_id、卡组与冻结证据引用、代码/解析/口径版本及必要时间边界。公开摘要不泄露实际账号和敏感标识，完整对应关系留受控目录。
- 从预先登记的批次和冻结来源重建参与列表，验证十个不同完整对局、先后与归属、同一冻结版本、所有启动记录的处理。重复局、缺局、失败局被删、未知归属、混合版本和人工接管都不能拼成合格批次。
- 根据核验的 N/E 重新执行整数阈值与 `0 <= N <= E` 等约束；不信任调用方传来的布尔结论。Unknown 与确认未填分开；只有证据成立的下界才允许用于“至少超过阈值”，不能冒充精确值。
- 加入 synthetic 经生产结果入口拒绝、相同 round 重复十次拒绝、缺少来源/预登记记录拒绝、混合版本/跨实例拒绝，以及合格十局夹具通过的组合测试。

**成功表现：**算术单元测试仍能运行；上述伪批次无法获得真实验收通过。通过结果能定位十个真实独立对局及各局分子分母来源，而不是仅有十条汇总字典。

**失败怎么办：**输出 Invalid / Insufficient evidence 并解释来源或批次缺口，不通过改标签、补齐复制结果、裁剪数值、舍弃失败局或修改分母凑过线。

### R3 / P1：布局失效必须同时使尚未发出的点击失效

**依据：**`tick()` 在提交线程任务前从 grid 计算 x/y，内部 `execute()` 实际执行时只检查 closed、halted 和 round_id；没有重验 grid 是否被撤销、layout_version 是否变化或布局是否过期。

最小复现使用延迟执行的模拟线程池：先令 `tick()` 排入一个合法目标，再撤销 `grid=None` 并改变 layout_version，然后调用已捕获的 execute 闭包。结果仍调用一次模拟 tap，使用排队前坐标。此过程没有 ADB 或游戏输入，只证明“排队到执行之间布局失效”的代码路径未拦截。

**做什么：**保留目标的 round/card/cell 身份，不把旧坐标当执行授权。增加执行代次或取消令牌；在实际发送输入前重验同局、前台、无阻挡、稳定布局版本与有效期。布局撤销/改变、切局或 STOP 时，取消尚未发送的旧动作；重新稳定后按当前坐标计算并合法重排。协调状态更新与执行检查，避免检查和发出之间的无保护交叉。

已发送到设备的输入无法保证撤销，这类结果应按事实记为 executed/unknown 并由后续数据核对；不得把排队数量当实际注入数量。新增三个真实执行闭包测试：排队后撤销布局不发 tap、排队后切局/STOP 不发 tap、重新标定后仅用新坐标执行。不能只让 mock.submit 返回一个从未执行函数的 Future 就宣布执行边界通过。

**成功表现：**尚未发出的过期动作不会点击旧位置，重新稳定后能够恢复同局有效目标，不造成永久漏排或跨局输入。

**失败怎么办：**暂停输入、保留采集与目标状态，在授权时限内恢复；无法判断设备是否执行时记 Unknown，不能盲重试或写成功。
