## 1. Goal：交付什么才算完成

交付能实际完成“普通四卡买卡 → 开局绑定 → 持续处理全部实际叫号目标 → 数据确认与有限补漏 → 合法窗口内收尾 → 结算 → 自动续局”的自动玩工具。User 启动后不需要逐格补点、替程序点击结算或手动纠正正常流程。

## 4. 执行步骤

### 步骤一：一次性完成接管和不消费票券的运行准备

**做什么：**读取最新 main、原 Task/Status/Handoff、三轮 Review、两份旧执行附件及本修订。保全原分支与未提交修改，核对只有一个控制者，沿用独立工作副本。把本文件作为 canonical 当前规范性附件，不要求策划逐条拼接历史指令。

复用已有只读设备访问，补齐主机、设备、客户端日志和抓包的时间关系。区分发生、记录、读取和发送时间；保存独立采样前后区间、误差、来源 epoch 与有效期。能用同一可信事件序列判断的，优先使用序列；跨时钟匹配使用有依据的区间，不拿日志读取时间冒充发生时间。当前校准不能回改旧局，也不能靠扩大窗口或固定减去旧样本差值制造匹配。控制器和核验器复用同一时间关联规则。

在购买前核对当前普通四卡配置、报价、资源状态、采集新鲜度、来源身份、记录能力和停止入口。只读检查记入现有控制运行账本；完全离线测试不算游戏资源消费。不要先买卡，才发现字段或时间根本无法绑定。

**成功表现：**出现具体可复查的运行准备结果，能说明当前来源和资源为什么可信；入口可以进入完整自动玩，而非固定返回“缺一局定位”。

**失败怎么办：**自行修复解析、读取、时间关联和配置问题，继续其余离线工作；身份、报价、实际叫号或停止能力不可信时不购买/不盲点。不得增权、修改系统时间或擅自重启采集器。

### 步骤二：接通持续四卡自动玩，不再执行一次就等结算

**做什么：**默认交付入口为“完整自动玩”，从本局开始持续处理全部合法目标。排查并移除该入口误继承的 `max_dispatches=1`、`diagnostic_slot`、只标定到第一次点击、达到一次点击后停止补扫等定位限制。不得只改提示而保留单击行为。

以同一实例/会话/round/card/cell 为目标身份，流程统一为：实际叫号到达 → 对应各卡目标入队 → 本局卡面及布局就绪 → 合法时机点击 → 观察确认/补漏 → 闭局前收尾。服务端提前提供的号码窗口只保留为来源候选，不能当成当前已叫号；实时决策以经验证的实际叫号来源为准。整局结束后才能用于审计的未来数据不能倒灌实时控制。

正常叫号、开局补排和周期补漏共用时机/布局检查。拿到卡面或布局恢复时，补齐本局已经实际叫过但尚未处理的目标。队列只保存目标身份，最后发送点使用当前有效坐标，复用批次/子会话 STOP、前台、布局代次和局号检查。

采集与客户端日志读取、布局采样、输入等待分离，不能等稀疏确认才处理下一个号码。调度必须防止旧目标长期被新球挤压，也不能让无限重试挤掉新目标；明确首次尝试、补救、目标等待时长和合法截止窗口的优先级。输入仍有序且有上限，不靠无节制并发。

**成功表现：**实际入口的合成整局会持续点击多个号码、多个卡和多个时段；开局/中期/末期都有处理，不受单击定位限制。开始实跑后交付的也是这一模式。

**失败怎么办：**保留目标和失败原因，修队列、状态或运行绑定；未发送目标恢复后重排，已发送但不确定的目标按步骤三处理，不把整局降成单击定位交付。

### 步骤三：可靠补漏，避免临近结束仍积压大量应填格

**做什么：**区分“未尝试、已发送待确认、确认已填、确认未填、特殊/未知、不能再操作”。attempted/tapped 只记录尝试，不代表成功；单次失败不得永久抹掉补救机会。

稀疏上行记录或时间匹配不足，只限制该格成功认定与风险不明的重复点击，不能无故停止其他可确定的新目标。复用经过验证的客户端接受状态或服务端状态；无须假设一定存在服务端逐格 ACK。禁止恢复 FIFO 假配。

补漏按目标限次、限速、限时。确认输入未执行、仍合法未填，或重复点击安全性已获证据支持时才重试。没有证据时不得盲目反复点；应优先重新读取该格状态、修正布局/时间关联并保留 Unknown。每格预算和整局输入预算要兼容补漏，不能用“首次最多 96 格”的全局限制提前耗尽合法重试空间。

已识别 PowerUp/特殊效果单独处理：不从应填分母删格，不把未验证效果计为普通成功，也不继续向可能已被效果处理的格子盲点；其余普通目标继续。特定效果未解开不要求全协议重做。

在合法窗口结束前处理剩余目标，尤其检查最早积压目标、末球多卡同号和慢输入。不能等到真正 GameOver 才开始补点；同时不能为补点而在窗口关闭后继续发送。固定运行超时与正常闭局分开。

**成功表现：**每个漏点有具体去向与原因，正常流程不依赖 User 补点；临近局末存在明显积压时，调度正在合法补救而非空等。目标仍按数据计算，现场大量闪动作为质量反馈保留，不用 N/A 否认现象。

**失败怎么办：**根据真实数据区分没排入、被限次、坐标不稳、输入未生效、确认缺失、人工接管或末尾超时，定向修复。不能只报告“证据不足”而不解释控制器实际做了什么。

### 步骤四：把可以运行与可以认证分开，并保持数据优先

**做什么：**提供两个不同判定：

1. `run_ready`：当前普通操作有明确实例与资源授权；卡组/实际叫号/布局/停止可信，采集和行为记录可追溯。它允许正常完整自动玩，不允许填充语义未知时伪造成功或冒险重复点击。
2. `metric_ready`：计量语义、同局归属、完整分母、关闭窗口和自动/人工贡献已由独立证据验证。它才允许输出可验收的精确率或可信下界。不能由控制器 done 集合、标签或手工 true 标志授予。

填充语义复核不再限定只能来自“整局只点一次、没有其他变化”的两次购买。先复用既有证据中的同源序列、明确卡格的状态变化和终态交叉核对；有人操作的局只能支持来源/语义研究，不能作为无人自动玩的成绩。至少覆盖两个独立对局和不同目标的语义一致性，排除包装、FREE、特殊效果和时钟不明片段，不把共现自动当因果证明。

所需跨局证据也可在下述完整自动玩批次中持续取得：启动前冻结候选语义、核验规则、版本和取样方法；每局都执行完整目标，不能为了补语义故意只点一次或漏掉其余格。语义确认后，独立核验器可按同一冻结规则复核本批所有原始证据；未达到证据要求的局保留不合格/未证明，不能删掉或改名。不得看完成绩再改语义、分母或阈值让批次过线。

图像仅辅助低频导航、前台/遮挡和几何标定；卡面数字、实际叫号、应填、已填和百分比均使用结构化数据。User 的目视漏点反馈单独标为现场反馈，不转成猜测百分比，也不作为持续截图识数的理由。

**成功表现：**安全且可记录的完整流程可以运行；核验仍然严格。某个格证据未知不会变成假成功，不会机械地挡住全部确定目标。生产结果与 synthetic 算术彻底分离。

**失败怎么办：**不可信操作暂停，不能认证的成绩保留 N/A/下界及具体缺口；继续可解决的修复。来源记录链根本无法恢复时不继续浪费后续局数。禁止简单删门槛、改标签、跨局借帧或重写旧证据。

### 步骤五：冻结候选，连续运行完整十局并统一交付

**做什么：**先通过原回归和下文新增整局/时间/模式回归，提交干净候选；登记实现/解析/计量版本、运行模式、实例、配置、全部 10 个位置和开始边界，再启动完整自动玩批次。开跑前在控制台明确：本次持续填充四卡全部合法目标，User 无需补点；显示局次、运行状态和停止入口。这是告知，不增加逐步骤审批。

第一局就是完整自动玩，不是换名字的定位局。同一批次逐局保留来源、动作、输入确认、状态变化、闭局、结算和续局结果。结算与下一局使用已有导航和数据身份核对，不要求 User 操作。人工接管如实记录，该局不作为无人自动玩成功；未归属输入不自动指责 User，先区分时钟/来源错误。

只因某局填充率低于目标，不删除或补替代局。非关键 Unknown 不单独终止所有后续工作；动作不安全、资源超限或记录链失效时停止相应消费。过程中不得偷改冻结版本；如发现必须改代码，保留本批未完成/失败结果，离线修复后不能混合版本凑成十局通过，也不自动增加启动名额。

**成功表现：**同一候选无人工纠错地完成 10 个对局及正常结算/续局，逐局来源核验通过且每局 >90%；报告加权是否达到 95%。这是完成标准，不是“启动命令不报错”。

**失败怎么办：**交付实际完成局数、逐局结果、已发生漏点和剩余原因；继续本 Task 内不需新资源的修复。需要额外真实启动或资源时一次说明最小差额，不隐藏旧失败，不自行加额，不谎称完成。

## 5. Acceptance：精确口径与观察结论分开

对每局 r：E_r 是本局实际四卡中、整局实际叫号对应的非 FREE 目标格集合；同号不同卡分别计数，同格重复事件只计一次。C_r 是在有效窗口内，有可信语义与来源确认的已填格集合，普通、特殊和未知状态不得混算。

N_r = |E_r ∩ C_r|；R_r = N_r / |E_r|。逐局按整数判断 `10*N_r > 9*|E_r|`，恰好 90% 不通过。整批按 `20*sum(N_r) >= 19*sum(|E_r|)` 判断 95%，不是各局百分比简单平均，也不靠显示四舍五入过线。

分母完整且已确认数可信时，允许报告 verified_lower_bound，明确它不是精确率；下界严格过线可以证明至少超过 90%。缺少分母/归属/语义的结果为未证明，不伪装达标。零分母 N/A，不算 100%。道具/未知、开局遗漏和末尾来不及点的目标不能为了提分事后移出分母。

每局报告应填、确认自动填、确认未填、Unknown、人工干预、完整流程是否结束和证据状态。现场反馈“局末大量可填格仍闪动”必须保留为漏点事实的 User 观察；精确率尚不可认证与现场存在漏点可以同时成立。人工补点不计自动成功，不能用最终亮格数掩盖程序此前没有填。

本任务最终通过需要：完整十局、无人纠错、数据核验有效、每局严格 >90%。47 项或更多离线测试、已有三局定位、当前未证明的 N/A 都不替代这一结果。
