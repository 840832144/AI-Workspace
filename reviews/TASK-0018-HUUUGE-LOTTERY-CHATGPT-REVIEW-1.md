## Required Fix 2 — 补齐本次真实充值 / 购买记录

User 明确确认游玩过程中发生了多次实际充值 / 购票，但当前报告只写“四次购买链路共发放 763 张票”，随后又称“实际货币价格不在证据中”，导致策划无法看到真实商业化路径。

现有业务目录已显示同一 Session 的 Lottery 购买请求中存在已填充的 `local_price`，购买请求中也存在 `local_currency_code`、`lottery_ticket_color`、`store_iap_id`、`product_id` 等关联字段。因此必须先重新核验本机 decoded evidence，再判断价格是否真的缺失；不能继续把 Extractor 未提取写成“采集证据没有价格”。

必须：

1. 重新读取本次 `MakeInAppPurchase` 请求 / 响应和奖励发放，按成功链路配对。
2. 使用 `request_id`、purchase / product 标识只在本机完成关联，不把真实标识写入 Git 或飞书。
3. 在脱敏事实层增加 `Purchase-1...N`，至少包含：
   - 是否成功；
   - 实际支付金额；
   - 币种；
   - 获得的票色与数量；
   - 同包其他奖励（如存在）；
   - 可否计算表观单票成本及限制。
4. 在正式报告增加“本次充值与购票记录”表，并给出总充值次数、总实付金额和各次获得内容。
5. 使用 User 的现场确认作为 Manual evidence，与 Runtime 购买链路核对；存在不一致时明确列出，不得静默取一边。

“付费票价格”在策划语境中应明确写为：

> 玩家使用真实货币购买某档票包所支付的金额、币种、获得票数，以及在礼包不含其他价值时可计算的单票价格。

若礼包同时包含筹码、忠诚度或其他奖励，只能写“礼包总价”和“表观每票成本”，不能把全部价格强行归因给票。

若重新核验后仍不能恢复价格，必须准确说明缺的是哪个字段、哪一步关联或哪段 UI / 商店证据，而不是笼统写“不能回答付费票价格”。

## Required Fix 3 — “付费”只能表示真实货币行为

当前“共 588 次付费 Spin”属于严重术语错误。这里的 Spin 只是消耗游戏筹码的普通下注，不是每次发生真实货币支付。

所有对外文档、飞书正文、图表和 CSV 展示名必须统一：

- `付费 Spin` → `普通下注` 或 `筹码下注`
- `588 次付费 Spin` → `588 次筹码下注，另有 45 次 Free Spin`
- `付费 Spin 成本` → `普通下注筹码消耗`
- `paid_spin_cost` 的策划展示名 → `regular_spin_chip_cost` / `普通下注筹码消耗`

内部兼容字段若暂时不能重命名，可以保留别名，但不得继续出现在策划报告中。

本项目以后统一口径：

- **下注**：玩家在老虎机中消耗筹码进行 Spin；
- **Free Spin**：不单独消耗本次下注筹码的免费旋转；
- **付费 / 充值 / 购买**：玩家实际使用真实货币完成的交易。
