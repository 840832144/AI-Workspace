# Bingo Voyage 自动玩（AutoPlay）设计与度量

> 目标：**填图率 ≥ 95%**（一个开了 Daub Alert 的正常玩家水平）。
> 填图率 = 已填格数 / 应填格数（理论最大填图）。
> 一切判断走**事件/参数**，只有「续局 / 返回大厅」这类导航才用图像。

## 1. 文件位置

| 文件 | 作用 |
|---|---|
| `D:\BingoVoyageProbe\bv_autoplay.py` | 自动玩主程序（事件驱动） |
| `D:\BingoVoyageProbe\bv_rate.py` | 填图率度量（会话级 + 合计） |
| `D:\BingoVoyageProbe\bv_cardgrid.py` | 卡位检测（截图 → 列/行锚点），每局重测 |
| `D:\BingoVoyageProbe\bv_diag_cards.py` | 诊断：卡面帧局号 vs 报号帧局号 |
| `D:\BingoVoyageProbe\sessions\autoplay_<ts>\` | 每会话产物目录 |
| `D:\BingoVoyageProbe\out\ap_run*.log` | 运行日志 |

会话目录内容：
- `session.json` —— 会话摘要（点击/回执/重试/放弃/错配/局号…）
- `actions.jsonl` —— 每个动作：`tap` / `retry` / `recycle` / `ack` / `ack_orphan` / `give_up`
- `events.jsonl` —— **本会话收到的全部帧**（其它事件也留档，便于日后追溯解析）
- `cards_in_round.json` —— **本局实际使用的卡面参数**（度量与复盘的唯一依据）
- `_grid.png` —— 本局卡位标定截图

## 2. 数据来源（全部是参数，不采样画面）

| 用途 | 来源 |
|---|---|
| 出球 | `cmd 169` S→C `{1:roundId, 2:[最近5个号，最右=最新], 3:roomPath}` |
| 卡面 | `cmd 163`（进局全量快照）/ `166`（买卡·换卡）/ `167`（状态串） |
| daub 回执 | `cmd 167` C→S subtype 1：`field2 = 卡号-1`，`field1 = 0基列主序格号` |
| 进局确认 | `cmd 202` C→S |

- 卡面编码：25 个数**列主序** B5 I5 N5 G5 O5；下标 12 是占位符，游戏里渲染成 FREE（**不计入应填**）。
- 严格分带 B1-15 / I16-30 / N31-45 / G46-60 / O61-75。
- 协议下标 → 视觉位置：`['tl','bl','tr','br']`（1→左上，2→左下，3→右上，4→右下），已由回执数据反证。

## 3. 满足的硬约束

1. **只点已经叫过的号**：`self.called` 是唯一白名单，不在里面的格一律不点。
2. **等客户端播完球再点**：`--settle`（默认 1.0s）延迟，避免「比出球还早点」导致点空。
3. **补排历史球**：卡面到手前已经叫过的号，用 `backfill()` 一次性补齐，消灭页面上一闪一闪的白数字。
4. **周期补扫**：`--rescan`（默认 1.2s）扫描所有卡面 × 已叫号，把漏掉的格子重新排入队列。
5. **卡面数自适应**：卡位数由卡面参数动态决定（1/2/4 张各有布局），不写死。
6. **卡位每局重测**：同布局不同局之间实测有 ~20px 漂移，`setup_grid()` 每局用 `bv_cardgrid` 重标定，内置表只做兜底。
7. **回执精确配对**：用 `(field2+1, idx2rc(field1))` 精确匹配等待中的点击，配不上才退化成 FIFO，并计入 `ack_mismatch`。
8. **不永久放弃**：连续无回执的格子先 `recycle` 回收重排（最多 2 轮），再记 `give_up`。

## 4. 关键限制：本局没买卡 ⇒ 没卡面（已取证）

实测时间线（`python D:\BingoVoyageProbe\bv_diag_enter.py`）：

```
10:59:15  C->S 202  进房买卡
10:59:16  S->C 163  局号 ...dQq4Vm7EL5oHT.11   卡面 4 张   ← 买卡后 1~2 秒下发
11:17:25  S->C 163  局号 ...uyVgA6OGLkJr9D.8   卡面 0 张   ← 没买卡，快照里没卡
11:19:45  S->C 163  局号 ...TkyWL9jrCF00eh.7   卡面 0 张
11:31:42  S->C 163  局号 ...qiTbIqJYddw0h.30   卡面 0 张
```

16 帧 `cmd 163` 里**只有 5 帧带卡面**，且全部紧跟在一帧 **C→S `cmd 202`（进房买卡）**之后 1~2 秒。
结论：

1. **卡面只在「玩家本局买了卡」时下发**。服务端每回合都会推 `163` 快照，但没买卡的那份快照里卡面为空。
2. 因此自动玩要跑完整局，**必须自己完成「买卡 / 进局」这一步**（发 `cmd 202`，或驱动 UI 的买卡按钮），否则整局无卡可点。
3. 这条限制同时也是早期「乱点数字」的根因：那几次点击用的是**别的局的陈旧卡面**。现在 `self.cards` 按局号严格绑定，拿不到就一格不点——所以 `.35/.36/.37` 三个回合自动玩**点击 0 次、误点 0 次**，安全约束按预期生效。

**冒烟测试用的正确时序**：先让客户端在局内买好卡（或补上自动买卡），再挂自动玩：

```powershell
# 1) 确认这一局真的有卡面下发
python D:\BingoVoyageProbe\bv_diag_cards.py
#    期望 S->C cmd 163 带卡面的帧 > 0

# 2) 再开自动玩（没卡面时静默等，不会乱点）
python D:\BingoVoyageProbe\bv_autoplay.py --seconds 420 --wait-round
```

`--wait-round` 无卡面时**只打印一次**提示，不误点、不刷屏。

## 5. 回执不是「一次一格」——重试风暴的根因（2026-10-13 实测）

一局完整实测（会话 `autoplay_20261013_115453`，局号 `td8q2PhLrHLCpxT7axT.16`）：

| 指标 | 数值 |
|---|---|
| 点击 | 404（首次 113 + 重试 291） |
| `cmd 167` subtype1 回执 | **23 条** |
| 重试 / 放弃 | 291 / 9 个球 |
| 回执按卡分布（field2+1） | 卡2 **7**、卡3 **6**、卡4 **4**、**卡1 = 0** |
| 点击按卡分布 | 卡1 54、卡2 15、卡3 23、卡4 21 |

结算截图（`sessions/autoplay_20261013_115453/_grid.png`）的**地面真相**：
四张卡上只剩 **4 个未点亮的格**（卡1 r4c1=9、卡2 r2c1=4、卡4 r2c1=3、卡4 r5c1=6）。

结论：

1. **卡1 在回执里 0 条，但结算画面它只漏了 1 格** ⇒ 客户端**明显 daub 成功了**，只是没发 `cmd 167` subtype1。
2. 所以 **subtype1 不是逐格回执**，而是稀疏上报（约每球 0~1 条，整局 23 条）。
3. 用「没回执就重试」判成败是**错的前提**，直接造出 291 次重试、404 次点击，把 daub 窗口白白打满。
4. 卡位标定本身没问题：结算截图上四张卡的实际栅格与检测值偏差仅 10~15px（小于半个格距 79px）。

**要改的三件事**：
- 点击改成**每格一次**（最多再补一次，间隔 ~0.6s），不再靠回执驱动重试；
- 已填状态改从 **`cmd 167` subtype9 状态串**（疑似 4×25 位图）或**结算画面**读取，而不是回执条数；
- 填图率口径随之改为「应填 − 结算残留未点亮格」。

## 6. 常用参数


| 参数 | 默认 | 说明 |
|---|---|---|
| `--seconds` | 200 | 运行秒数（有界，不常驻） |
| `--wait-round` | 关 | 无卡面时静默等下一局开局 |
| `--settle` | 1.0 | 出球后延迟多久点 |
| `--ack-wait` | 1.0 | 点完等回执的秒数（< 出球间隔 5s） |
| `--retries` | 3 | 无回执重试次数 |
| `--inflight` | 3 | 同时允许多少个点击在等回执（防串行饿死） |
| `--rescan` | 1.2 | 周期补扫间隔 |
| `--auto-next` | 关 | 一局结束后自动续局（走图像导航） |
| `--dry` | 关 | 只算不点 |

## 7. 度量

```powershell
python D:\BingoVoyageProbe\bv_rate.py                 # 全部会话合计
python D:\BingoVoyageProbe\bv_rate.py <会话目录>       # 单个会话
```

口径：
- **应填** = 会话时间窗内已叫号中，命中我卡面的格（FREE 除外）
- **已填** = `actions.jsonl` 里 `kind=ack` 的去重格
- **填图率** = 已填 / 应填，目标 ≥ 95%
- 卡面优先级：会话自带 `cards_in_round.json` → 全局 `data/cards.jsonl`（按局号精确匹配）
