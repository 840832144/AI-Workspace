## 5. Scope：卡包范围和美元口径

### 5.1 卡包范围

覆盖目标赛季实际存在的全部普通星级卡包，不预设只能有 1—5 星。首页按星级排序；明细以 packId 为主键，保留 itemId、名称、星级、普通/金卡/付费/免费/专用等实际存在的变体、适用进度、张数及规则。

同星级、同 itemId 但不同 packId、内容、概率或场景的包不能强行合并。只有已证明开包结果与估值条件等价时才汇总，并保留对应 ID 列表。未投放、过期、未解锁替代包单列其身份；只有 101 真有相应机制时才扩展金包/Joker 等行，不自行造类别。

### 5.2 默认用途与报告单位

默认给策划的主值是“用于奖励预算比较的每包美元等价值”。必须先确定并展示一个明确的 101 美元基准及适用等级/VIP/币种单位；不能混用活动奖励的名义美元、商城币价、金币反算美元或真实支付金额。

固定区分三类列，不互相冒充：

1. **配置定价/内部面值**：只在 101 存在可证明语义的显式价值字段、正式标准表或已批准方案时填写。字段叫 price/value 不足以证明单位是美元。
2. **模型估值**：依据实际开包概率、奖励及可兑现条件，在明确状态/时间窗/策略下计算；标记 Estimate。作为主表参考值时必须展示所选基准情景，未经 User 接受不称已批准的统一定价。
3. **实际售价或礼包分摊参考**：仅在已有真实 USD 商品映射且适用条件清楚时单列。复合礼包不能把总价直接除以包数；没有独立其他道具估值和可识别分摊依据就保留 N/A，不真实购买、不访问账号数据。

若 101 确认某奖励字段使用“美元×100”，才进行该换算。名义金额、按真实代码查档得到的金币、按选定统一基准折算的美元分开列；检查缺档、取整、上/下选档、等级/VIP和加载顺序，不用 CR 的具体档位或线性比例替代 101 实现。

### 5.3 估值方法选择

优先采用 101 已有且来源明确、适用于当前输入的正式内部估值方法，复算后用于主表；CR 历史公式只能在逐项说明适配依据后复用其结构。现有方法不适配时，先用解析计算、有限结果枚举或已有模拟工具，只有状态反馈确实需要才写最小离线模型，不开发通用报告/采集平台。

若每张卡已有经过验证、可加总的独立内部美元面值，可用真实边际概率计算各槽位期望并汇总，但必须解释包内去重、条件重抽、固定卡及少发如何影响分布。不能默认卡的星级就是价值，也不能把一包标称张数当作实际必发张数。

没有直接估值时，采用明确有限时间窗下的整包边际奖励模型：

`V_pack(p | s,h,π) = E_B[即时新增奖励(s,B) + F(T(s,B),h,π) - F(s,h,π)]`。

其中 s 是已明确的玩家/卡册状态，h 是剩余时间，π 是固定后续策略，B 是按 101 真实规则生成的整包结果，T 是开包后的状态，F 只包含未来奖励，不再次包含已经计入的即时奖励。后续获得包计划、兑换策略和同一币值单位在有包/无包两条路径中保持可比。

模型需按 101 实际存在的规则处理新卡、重复卡/星星兑换、整章/整册奖励、普通册到进阶册重置、到期损失、保底及权重档。不要把章节与整册总奖励重复分配给卡片后再次叠加；不要用“星星换包—包产星星”的闭环任意固定一个美元锚点。

不能用“整册总奖励÷卡数”“按星级线性加价”“金币固定乘 CR 汇率”直接给出确定单价。获取成本、Spin 损耗及礼包分摊不是奖励期望收益，不混加到主值；本轮不为估算成本额外开展 RTP/机台实测。

## 6. 情景与主表落地

存在可信内部面值时，先交面值主表，再用最小必要情景解释局限。没有可信固定面值时，对同一 packId 给出清楚标识的条件估值；主表显示所选基准情景的参考值和其他情景范围，不伪造全服统一均价。

至少选取能解释差异的“新册/低收集进度、中期、接近集齐或季末”状态；真实有进阶册时补充重置初期。状态必须列明具体 cardId/持有分布的构造方法，而不是只用一个笼统百分比替代不同缺卡结构。只缺普通卡、只缺金卡等仅在规则支持且影响结论时补充。

没有真实玩家分布时使用可复算合成状态，标记 Hypothesis，不把等权平均或模拟参数当线上人群。至少报告同星级变体差异、包间价值倍率和主要敏感项；参考价值非单调时解释配置或情景原因，不为“看起来合理”强制调成递增。

美元基准或关键加载规则实在不可识别时，仍交包规格、概率、期望结果与符号/区间模型，受影响 USD 列为 N/A，给出最小可补输入。不得把空值写成 0 美元或伪造无限置信的点估计。
