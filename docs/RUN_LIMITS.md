## 1. 已批准的运行边界

| 项 | 批准值 | 记录来源 | 代码是否强制 |
|---|---|---|---|
| 单次运行时长 | `--seconds` **≤ 300**，单次单局 | 本次整理时确认 | ❌ 无硬上限，需调用方自觉 |
| 运行形态 | **非常驻**（跑完即退，不挂后台） | `collector/README.md:23`、`FINDINGS:242` | ❌ |
| 单局押注 | **≤ 4 张卡 / 底注 8 票** | 游戏面板默认档，见 §3 | — 由游戏侧限制 |
| 单次会话局数 | **1 局**（不自动连续多局） | 本次整理时确认 | ❌（`--auto-next` 可连跑，默认关） |
| 原始数据入库 | **禁止**（`*.jsonl`/`*.bin`/截图/APK 不入版本库） | `.gitignore` + `HANDOFF.md §8` | ✅ |

**「非常驻」的含义**：所有脚本必须带 `--seconds N` 有限时长，进程自行退出；
不得以守护/轮询形式长期挂在设备上。

## 3. 实测资源消耗（供定量用）

### 3.1 押注与卡数（来自 `BET_S001_001_INFLATION` 表）

```
底注档位   1 / 2 / 3 / 5 / 10 / 15 / 20
最大卡数   1 / 2 / 3 / 4 /  5 /  5 /  5
```

实测面板：**4 张卡 = 8 票**，**1 张卡 = 2 票**。

### 3.2 账号观察值（2026-10-13，新账号）

| 指标 | 观察值 |
|---|---|
| 票余额 | 49 ~ 56（每局结算返票 +0 ~ +3） |
| B 币余额 | 3 ~ 133 |
| 单局奖励形态 | 票 +N、B币 +N、拼图 +1、XP +N |
| 等级 | L1 → L4（1,500 / 2,000 / 2,200 / 4,100 XP） |

**结论：票不是瓶颈。** 单局 8 票、返票 0~3，一小时连打约 30 局也只消耗 ~150 票，
而实测余额长期在 50 上下浮动且有富余。真正的约束是**时长与局数**，不是票。

### 3.3 单局耗时与动作量

| 指标 | 实测 |
|---|---|
| 单局时长 | 约 2 分钟（报号 5s 一个，约 24~36 个号） |
| 单局点击 | 26 ~ 43 次（`--retries 0` 后为 26 次量级） |
| 单次运行窗口 | 130 ~ 170 秒（覆盖一整局） |
| 抓包产出 | 单局约 3,000 帧 / 数 MB body |

## 4. 每次运行前的自检清单

```powershell
# 1. 截图必须是竖屏
adb -s 127.0.0.1:16384 exec-out screencap -p > x.png
# 尺寸需为 (900,1600)；若是 (1600,900) 先修横屏（见 HANDOFF §2 坑 1）

# 2. CA 命名空间（游戏重启后必跑）
adb push dev/bv_ca_fix.sh /data/local/tmp/
adb shell sh /data/local/tmp/bv_ca_fix.sh
# 验证：游戏 pid 的 apex certs = 146

# 3. 链路在跑
python collector\bv_collect.py status

# 4. 跑一局（带时长上限，跑完即退）
python bv_autoplay.py --seconds 135 --rescan 1.2

# 5. 出填图率（纯协议数据，不用截图）
python bv_count9.py sessions\<会话目录>
```
